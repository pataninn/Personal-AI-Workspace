## Settled contract decisions

- The effective policy is persisted per authenticated owner and exact Home/project scope. A Home turn that targets a workspace intersects the account Home policy with the exact owner/project policy. It derives the target from an owner-scoped persisted resource and checks the current revision again before every later dispatch and durable write.
- The stored scope uses fixed versioned profiles `home_in_scope_v1` and `workspace_in_scope_v1`, which map in code to bounded context categories and tool capabilities. Project item selection and exclusions continue to come only from `project_chat_contexts`. Missing rows are unavailable; GET and dispatch do not lazily seed them. Migration backfills eligible existing scopes and trusted account/project provisioning creates new ones after the table exists.
- The provider/model pair is exact configuration or null/null. A trusted synchronizer may fill a null pair only on an enabled, unrevoked row and increments its revision; it cannot replace a configured pair or revive a revoked row. Task 3.1's per-attempt admission and verified readiness remain separate.
- All legacy consent, proposal acceptance/execution, workspace egress, change-set, and sandbox-command decision endpoints return `409 POLICY_ACTION_RETIRED` for every decision value, including deny/reject; they make no state change and cause no runtime/provider/tool continuation. Proposal edit/remove is also retired. Authenticated cancellation and owner-scoped GET/history/status remain. This follows the observed Home tool-result-deny and sandbox-reject runtime continuation paths, so no phase-specific denial exception is safe.
- Main owns the post-`1710000031000` migration and registration, `backend/src/app.ts`, `backend/src/composition-root.ts`, auth/session plumbing, and account/project/demo/clone provisioning integration. Task 4.1 feature ownership requires a later file-level handoff after Task 3.3; the six protected working-tree files listed below remain outside this source-map task and must not be staged as incidental changes.
